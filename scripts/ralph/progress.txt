## Codebase Patterns
- Python interpreter: ALWAYS venv/bin/python (repo virtualenv at verax_backend/venv). New deps: venv/bin/pip install X && add to requirements.txt.
- Models: app/models/models.py uses Base from app.database.database; follow its Column style. Money columns: Numeric(14,6), Python Decimal.
- Routers: app/routers/*.py, registered in app/main.py via include_router. Auth: get_current_user dependency in app/routers/auth.py.
- Tests: temp SQLite via Base.metadata.create_all — never the dev Postgres. Real statement fixtures + ground truth: tests/fixtures/statements/ (expected_values.json keys = {period}_{account_code}).
- Statement parsing ground rules (verified on 2,612 real files — PRD §2): XLSX header row may not be row 1 (scan for 'Period' cell); last row is a grand-total row (only Earnings non-null) — exclude from lines, capture as embedded_total; header typo 'WrtierSplit%' is real; PDF text has spaces inside words ('Payable am ount') — patterns need \s* tolerance; account codes match [A-Za-z0-9]+(?:-New)?; pairing keys on (period, account_code) never display name.
- Pre-existing user WIP (auto_register_enabled in models.py/auth.py) must be committed separately once, never reverted (see scripts/ralph/CLAUDE.md).
- Python is 3.9 (venv) — no 3.10+ syntax (no `X | Y` unions, no match). SQLAlchemy is 1.4-style declarative_base (MovedIn20Warning is pre-existing noise).
- Settings REQUIRE env var ENVIRONMENT (e.g. DEVELOPMENT → loads .env.development). tests/conftest.py sets os.environ.setdefault("ENVIRONMENT", "DEVELOPMENT") BEFORE any app import. Run checks as: ENVIRONMENT=DEVELOPMENT venv/bin/python -c "import app.main".
- Statement storage root: app/services/statement_ingest/storage.py — get_storage_root() reads STATEMENTS_STORAGE_ROOT env at CALL time (tests monkeypatch.setenv it to tmp_path), defaults to <repo>/storage/statements. incoming_dir(upload_id) = {root}/incoming/{id}. US-004 sorter should add a helper here for {root}/{period_code}/{catalog}/.
- Admin gate: app/routers/statements_admin.py require_admin (Depends(get_user) + ADMIN_EMAILS env, comma-separated, case-insensitive, empty -> 403). Reuse for all /admin/statements/* endpoints. API tests: build a minimal FastAPI app with just the router + dependency_overrides[get_session/get_user] — do NOT TestClient app.main (import runs create_tables() against dev Postgres and lifespan starts the scheduler).
- Statement domain models: app/models/statements.py (snake_case tables per PRD §5), registered on Base via import at the BOTTOM of app/models/models.py. Enums: PyEnum classes, DB stores enum NAMES (e.g. 'MECH', 'SEMIANNUAL'). Migrations: hand-write (autogenerate would need the live Postgres); shared Postgres enum types via postgresql.ENUM(create_type=False) + explicit .create(bind, checkfirst=True) in upgrade(). Alembic config lives at migrations/alembic.ini; current head: n9o0p1q2r3s4.
- Test fixtures in tests/conftest.py: `engine` (scratch SQLite tmp_path with full schema) and `session`.
- Filename parsing: app/services/statement_ingest/filename_parser.py — parse_statement_filename(name) -> ParsedStatementFilename(period_code, cadence, account_code, display_name, royalty_type: Optional[Catalog], file_kind 'pdf'|'xlsx', is_house) or None. Sorter (US-004) should key pairing on (period_code, account_code) from this. Royalty type may be None (no parens in name) -> infer catalog from batch context. Python 3.9: no scoped inline regex flags (?i:...) — handle case-insensitivity manually (e.g. ext.lower()).
